# Prompt Evaluation

Writing a good prompt is just the beginning. To build reliable AI applications, you need **prompt evaluation** — measuring how well prompts actually work through automated testing.

## Prompt Engineering vs Prompt Evaluation

- **Prompt Engineering** — techniques for writing better prompts (multishot, XML tags, chain of thought, etc.)
- **Prompt Evaluation** — automated testing to measure prompt effectiveness objectively (test against expected answers, compare versions, review outputs for errors)

## Three Paths After Writing a Prompt

**Option 1** — Test once and decide it's good enough. High risk of breaking in production on unexpected inputs.

**Option 2** — Test a few times and tweak for a corner case or two. Better, but users provide far more variety than you anticipate.

**Option 3 (correct)** — Run through an evaluation pipeline to score it, then iterate based on objective metrics. More upfront work, much more confidence in reliability.

Options 1 and 2 are common traps. Real users interact in ways you never anticipated during limited testing.

## A Typical Eval Workflow (5 Steps)

### Step 1: Draft a Prompt

```python
prompt = f"""
Please answer the user's question:

{question}
"""
```

This basic prompt serves as the baseline.

### Step 2: Create an Eval Dataset

Test cases that represent the types of questions your prompt will handle in production. Can be assembled by hand or generated by Claude. In real-world evaluations: tens, hundreds, or thousands of records.

Example dataset:
- "What's 2+2?"
- "How do I make oatmeal?"
- "How far away is the Moon?"

### Step 3: Feed Through Claude

Merge each test case with the prompt template and send to Claude.

```python
def run_prompt(test_case):
    prompt = f"""
Please solve the following task:

{test_case["task"]}
"""
    messages = []
    add_user_message(messages, prompt)
    output = chat(messages)
    return output
```

### Step 4: Feed Through a Grader

The grader evaluates quality by examining both the original question and Claude's answer. Scores typically 1–10.

```python
def run_test_case(test_case):
    output = run_prompt(test_case)
    score = grade(output, test_case)   # grading logic here
    return {
        "output": output,
        "test_case": test_case,
        "score": score
    }

def run_eval(dataset):
    results = []
    for test_case in dataset:
        result = run_test_case(test_case)
        results.append(result)
    return results
```

Example scores: math question 10/10, oatmeal question 4/10, moon question 9/10 → average 7.66.

### Step 5: Change Prompt and Repeat

Modify the prompt (e.g., add "Answer with ample detail"), rerun the full eval, compare scores. If the new version scores 8.7 vs 7.66 baseline, the change is an objective improvement — not just a different variation.

## Why This Matters

This systematic approach removes guesswork from prompt engineering. You get:
- Objective numerical comparison between prompt versions
- Confidence that changes are real improvements
- Detection of weaknesses before they become production issues

The pipeline is conceptually simple: dataset → Claude → grader → score → iterate. The complexity comes in better prompts, sophisticated grading, and performance optimizations — not the pipeline structure itself.
