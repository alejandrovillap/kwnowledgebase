# Framework Equivalence — TPS / Agile / PMI / Lean / Six Sigma

Cross-framework equivalence table mapping Toyota Production System (TPS) concepts to their Agile/Scrum/Kanban, PMI/PMBOK, Lean, and Six Sigma counterparts.

| TPS Concept | Agile / Scrum / Kanban / XP | PMI / PMBOK | Lean | Six Sigma | Frequency | Work Unit | Learning Type | Level | Main Artifact |
|---|---|---|---|---|---|---|---|---|---|
| **TPS as a system** | Agile mindset / delivery system | Adaptive lifecycle tailoring | Lean management system | Continuous improvement / operational excellence | Continuous | Value stream | Systemic | Organization | Work system, principles, standards |
| **Jidoka** | Built-in quality, DoD, automated tests | Quality management, QA/QC | Built-in quality | Defect prevention, control plan, error proofing | Continuous / by default | Increment, story, operation | Preventive and corrective | Team / flow | Acceptance criteria, DoD, quality alerts |
| **Andon** | Blocker escalation, impediment board, build breaker alert | Issue log, escalation path | Visual control of abnormality | Control chart alert, special cause signal | Immediate | Incident, blocker, defect | Reactive immediate | Team / flow | Andon board, visual alert, visible blocker |
| **Kaizen** | Sprint retrospective, inspect and adapt, improvement backlog | Lessons learned, continuous improvement actions | Kaizen | DMAIC Improve/Control (incremental) | Each sprint / continuous | Team work process | Incremental and experiential | Team | Retrospective actions, improvement backlog, A3 lite |
| **Hansei** | Deep retrospective, reflection workshop | Lessons learned review, post-project reflection | Reflection / self-reflection | Root cause analysis after project review | Periodic / by milestone | Result, decision, behavior | Reflective | Team / organization | Reflection notes, lessons log |
| **Genchi Genbutsu** | Gemba walk, observe the work | Stakeholder/site observation, direct verification | Go and see | Data collection at source / voice of process | When doubt arises | Real work in context | Empirical | Flow / organization | Observation notes, on-site evidence |
| **Gemba** | Team workspace, workflow board | Operational site / delivery site | Gemba | Process observation site | Permanent | Place where value is created | Contextual | Team / flow | Board, work area, visual management |
| **Just-In-Time** | Pull delivery, small batch delivery | Progressive elaboration, adaptive delivery | JIT | Flow pull + reduce waiting/inventory | Continuous | Demand / ready item | On-demand | Flow | Replenishment signal, backlog ready item |
| **Pull system** | Kanban pull, ready-for-next-item | Adaptive sequencing, work authorization | Pull system | Pull-based flow control | Continuous | Ready item / available capacity | Flow | Flow | Pull signal, explicit policy, Kanban card |
| **Kanban** | Kanban, WIP limits, visual workflow | Visual control, workflow governance | Kanban | Flowchart / process visualization | Daily / continuous | Card, item, service class | Flow and constraint | Flow / team | Kanban board, WIP policy, service classes |
| **WIP limits** | Work-in-progress limits | Capacity management, workload control | WIP limits | Capacity control / process stability | Continuous | Work in progress | Flow | Flow / team | WIP limit, entry policy |
| **Heijunka** | Capacity leveling, release smoothing | Resource leveling, schedule smoothing | Leveling | Statistical process smoothing / load variation reduction | Periodic | Aggregated demand / capacity | Stabilization | Flow / organization | Level plan, release plan, average capacity |
| **Muda** | Waste removal, reduce ceremony overhead | Eliminate non-value-added work | Waste | Lean waste reduction / defect reduction | Continuous | Activity / wait / rework | Efficiency | Flow / organization | Waste map, waste log |
| **Mura** | Stabilize velocity, reduce variability | Variance reduction, risk mitigation | Unevenness | Variation reduction / control chart focus | Continuous | Load / flow / demand | Stability | Flow | Variation metrics, stable forecast |
| **Muri** | Sustainable pace, avoid burnout | Resource management, realistic workload | Overburden | Overload reduction / capacity balance | Continuous | Human / technical capacity | Sustainability | Team / organization | Workload, capacity, stress signal |
| **Poka-yoke** | Validation rules, TDD, automated checks | Preventive controls, QA controls | Mistake-proofing | Error proofing / defect prevention | In design and execution | Process step / validation | Preventive | Team / flow | Validation rule, checklist, automated test |
| **Standardized work** | Working agreements, DoD, team norms | Standard procedures, process assets | Standard work | Control plan / standard work instructions | Continuous / periodic review | Standard process | Cumulative | Team / organization | SOP, DoD, playbook |
| **PDCA** | Sprint cycle, inspect and adapt | Monitor and control + lessons learned | PDCA | DMAIC as structured variant | Iterative | Work cycle | Scientific / iterative | Team / organization | Improvement plan, results, adjustment |
| **Visual management** | Scrum board, Kanban board, information radiator | Dashboards, status reporting | Visual control | Control chart / dashboard / process map | Daily / continuous | Work status | Transparent | Team / flow | Visual board, traffic lights, metrics |
| **Daily management** | Daily Scrum, stand-up | Frequent status review / governance cadence | Daily management | Control phase / short-cycle review | Daily | Blockers, focus, progress | Operational | Team | Daily board, impediment log, action list |
| **5 Whys** | Root cause analysis in retrospective | Root cause analysis, issue analysis | Root cause analysis | Root cause analysis / variation cause analysis | When problem occurs | Incident / deviation | Causal | Team / flow | 5 Whys worksheet, problem statement |
| **A3 thinking** | Problem-solving workshop | Business case / corrective action plan | A3 problem solving | DMAIC project charter + storyboard | As needed | Problem / opportunity | Structured | Team / organization | A3 report, problem statement, countermeasures |
| **Obeya** | Big room planning, team-of-teams room | Integrated governance room | Big room / visual management | Project dashboard room / control room | By cadence / program | Portfolio / program | Integration | Program / organization | Obeya room, visual walls, program board |
| **Nemawashi** | Pre-alignment, stakeholder pre-briefing | Stakeholder engagement, change readiness | Consensus building | Pre-decision analysis and alignment | Before key decision | Decision / change | Relational | Organization | Stakeholder map, alignment notes |
| **Respect for people** | Servant leadership, self-managing teams, psychological safety | Team empowerment, stakeholder engagement | Respect for people | Cultural and leadership focus | Permanent | People / relationships | Human / cultural | Team / organization | Working agreements, coaching norms |
| **Lesson learned loop** | Retrospective action items back to backlog | Lessons learned register and reuse | Continuous improvement loop | DMAIC Control + transfer of control plan | Each sprint / closing | Identified improvement | Organizational | Team / organization | Lessons learned log, action tracker |
