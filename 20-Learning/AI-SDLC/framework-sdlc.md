# Framework SDLC

Detailed breakdown of Software Development Lifecycle phases and activities.

## 1. Discovery

1. Stakeholder identification
2. Requirements elicitation
3. Market and competitive analysis
4. Technical feasibility assessment
5. Risk identification and analysis
6. Project scope definition
7. Business case development
8. Definition of personas and user journeys

## 2. Planning

1. Project plan deliverables
2. **Resource allocation**: Matches project tasks to team members based on skills and availability; ensures essential resources (tools, budget, time) are allocated proficiently.
3. **Project schedule establishment**: Creates a detailed timeline with milestones, deadlines, and task dependencies. A roadmap to keep everyone on the same page about when each task needs to be completed.
4. **Risk management planning**: Identifies potential risks and outlines mitigation plans. A proactive approach to prevent problems before they occur.
5. **Budgeting**: Estimates cost of each task, calculates overall project budget, tracks expenditures.
6. **Quality metrics definition**: Defines quality standards against which the project's performance and output will be evaluated.
7. **Communication plan development**: Plans how project information will be communicated to team members and stakeholders (method, frequency, type).

## 3. Analysis

1. **Requirements gathering and data analysis**: Collecting, analyzing, and refining stakeholder needs through interviews, surveys, and discussions.
2. **Data analysis**: Inspecting, cleaning, and modeling data to discover useful information and support decision-making.
3. **Use case analysis**: Identifying, defining, and organizing system requirements — usage scenarios, user interactions, usage patterns.
4. **Process modeling**: Graphically representing enterprise processes using diagrams, flowcharts, and data models.
5. **Detailed feasibility analysis**: Evaluating technical requirements, constraints, ROI, and securing management buy-in.
6. **Requirements documentation**: Recording system requirements in a structured manner — functional, non-functional, system, and user requirements.
7. **Requirements prioritization**: Ranking requirements by importance, value, and feasibility.
8. **Requirements validation and stakeholder approval**: Validating accuracy, completeness, and feasibility; obtaining approval from all stakeholders.
9. **High-level testing plan**: Formulating a comprehensive strategy to test software functionality and reliability.

## 4. Design

1. **User experience design (UX)**: Focuses on user satisfaction through usability and enjoyment. Research, design, development, and continuous evaluation.
2. **User interface design (UI)**: Crafting visually appealing and interactive interfaces. Includes prototyping and user testing.
3. **System architecture design**: Structures software to be efficient and scalable. Component organization, technology selection, data flow design.
4. **Database design**: Optimizes data storage, access, and manipulation. Defines schemas, normalizes data, uses indexes, ensures security.
5. **Test design**: Defines features, designs test cases, and plans environments. Emphasizes comprehensive coverage, early testing, and automation.

## 5. Development

1. **Coding**: Turning designs and specifications into executable code. Select languages/frameworks → write → test → debug → review → integrate → deploy.
2. **Unit testing**: Tests individual components in isolation to ensure correctness. Tools: JUnit, pytest.
3. **Debugging**: Identifying and resolving issues — spotting the problem, isolating and reproducing, analyzing code, implementing fixes.
4. **Code review**: Peers examine each other's code to ensure it meets standards and is of high quality. Uses tools like GitHub with constructive feedback and automated checks.
5. **Code integration and deployment**:
   - **CI (Continuous Integration)**: Developers frequently merge code changes into a central repository; automated tests ensure early error detection. Tools: Jenkins, TeamCity.
   - **CD (Continuous Deployment)**: Automated process that quickly releases tested code changes to production with minimal human intervention.
6. **Technical documentation**: User guides, technical manuals, installation instructions. Should be audience-specific, easy to understand, and regularly updated.

## 6. Testing

1. **Test execution**: Running test cases to evaluate software behavior; documenting outcomes and deviations.
2. **Defect management**: Identifying, tracking, and resolving problems or errors found during testing.
3. **Test analysis**: Analyzing results to understand if tests were effective and what they revealed about functionality.
4. **Test reporting**: Documenting and communicating test results — execution status, defect metrics, coverage, and action recommendations.
5. **User Acceptance Testing (UAT)**: End-users evaluate software to ensure it meets requirements and expectations before deployment. Final validation step.
